# Гео-кластер: план вывода в топ-10

Дата: 06.09.2026. Данные: GSC 05.06–04.09.2026, проверка страниц вживую 06.09.2026.

Кластер: русские страницы `/ru/uslugi/lokacii/*` — 107 запросов, 1 682 показа, медиана позиции 19,6, ноль кликов.
Это единственная группа страниц сайта, стоящая на первой-второй странице выдачи.

---

## 0. Блокер: одна страница отдаётся по неограниченному числу URL

**Проверено вживую 06.09.2026 запросами к продакшену.**

Любой путь, последний сегмент которого совпадает со слагом существующей страницы, отдаёт эту страницу
с кодом 200 и с `canonical`, указывающим на **запрошенный** URL, а не на настоящий:

| Запрошенный URL | Код | canonical |
|---|---|---|
| `/pl/oferty/lokalizacje/pozycjonowanie-na-rynek-brytyjski` | 200 | сам на себя |
| `/pl/lokalizacje/pozycjonowanie-na-rynek-brytyjski` | 200 | сам на себя |
| `/pl/foo/bar/pozycjonowanie-na-rynek-brytyjski` | 200 | сам на себя |
| `/foo/seo-for-uk-market` | 200 | сам на себя |
| `/ru/lokacii/prodvizhenie-na-frantsuzskiy-rynok` | 200 | сам на себя |

Причина в коде: `src/app/[lang]/[...slug]/page.tsx` ищет документ по **последнему сегменту** пути
(`const current = slug[slug.length - 1]`), а `generateMetadata` строит canonical из запрошенного
`pathname`, а не из настоящего пути страницы. `dynamicParams = false` при этом фактически не отдаёт 404.

Второй дефект того же места: несуществующий слаг (`/pl/nieistniejaca-strona-testowa`) отдаёт
**200 и пустую страницу без title и H1** вместо 404.

### Почему это блокирует гео-кластер

Google уже проиндексировал польские гео-страницы в двух разных семействах URL одновременно:

- `/pl/oferty/lokalizacje/pozycjonowanie-na-rynek-brytyjski` — 206 показов
- `/pl/lokalizacje/pozycjonowanie-na-rynek-francuski` — 92 показа
- `/pl/lokalizacje/pozycjonowanie-na-rynek-szwajcarski` — 57 показов
- `/pl/oferty/lokalizacje/pozycjonowanie-na-rynek-amerykanski` — 57 показов
- `/pl/lokalizacje/pozycjonowanie-na-rynek-niemiecki` — 46 показов

Это ровно то, что GSC показывает как «Дубль, Google выбрал другой канонический» и частично объясняет
58 страниц «просканирована, но не проиндексирована». Любые правки текста до этой починки будут
распределяться между двумя URL одной страницы.

### Что чинить

1. **Резолв по полному пути.** После получения документа сверить запрошенный `slug[]` с настоящим путём
   страницы из `getAllPathsForLang(lang)`. Не совпало — `notFound()`. Одна проверка закрывает весь класс
   дублей.
2. **Canonical из настоящего пути**, а не из запрошенного `pathname` — и в `generateMetadata`, и в JSON-LD.
3. **Настоящий 404** для несуществующих слагов: сейчас 200 с пустой страницей.
4. **301 с неправильного польского семейства на правильное.** Судя по редиректу хаба
   (`/pl/lokalizacje` → 301 → `/pl/oferty/lokalizacje`), правильная цепочка — `oferty/lokalizacje`,
   значит `/pl/lokalizacje/<страна>` должен отдавать 301 на `/pl/oferty/lokalizacje/<страна>`.
   Эти URL уже в индексе с показами — им нужен редирект, а не 404.

## 1. Главная правка по контенту: страницы написаны не теми словами, которыми ищут

Страницы сильные — 2 100–2 200 слов, нормальная структура H2/H3, FAQ, перелинковка. Проблема не в объёме.

Проблема в формулировке. Подсчёт вхождений на странице Франции:

| Форма | Вхождений |
|---|---|
| «французск\*» (прилагательное + рынок) | 87 |
| «Франци\*» (название страны) | 38 |
| «во Франции» (предложный падеж) | 10 |
| «раскрутк\*» | 2 |

При этом запросы выглядят так: `seo франция`, `раскрутка сайта франция`, `продвижение сайтов во франции`,
`продвижение сайта во франции`. То есть люди ищут **названием страны**, а страница почти везде написана
**прилагательным + «рынок»**. Title и H1 — «SEO-продвижение сайта на французский рынок» — не содержат
ни «Франция», ни «во Франции».

На швейцарской странице картина та же: прилагательное 41, название страны 25, предложный падеж 8,
«раскрутка» 2.

Косвенное подтверждение: единственный H2 со словом «раскрутка сайта» есть на обеих страницах, и запрос
`раскрутка сайта франция` стоит на позиции 10,0 — лучше, чем `seo франция` (16,9) при меньшей частотности.
Это не доказательство, но направление совпадает с тем, что видно по всем страницам кластера.

### Что менять на каждой странице

1. **Title** — добавить название страны в той форме, которой ищут, и синоним «раскрутка».
   Было: `SEO-продвижение сайта на французский рынок | Bandziuk`
   Стало: `Продвижение сайта во Франции: SEO и раскрутка под французский рынок | Bandziuk`
2. **H1** — название услуги в единственном числе, словами запроса, а не внутренним термином.
   Было: `SEO-продвижение сайта на французский рынок`
   Стало: `Продвижение сайта во Франции`
3. **Один новый H2** под синоним, по стандартному правилу (понятен вне контекста + содержит ключ):
   `Чем раскрутка сайта во Франции отличается от продвижения в русскоязычном поиске`
4. **Переписать существующие H2** так, чтобы хотя бы в двух из них было название страны, а не только
   прилагательное. Сейчас во всех H2 — «французский рынок».
5. **FAQ — вопросы формулировками запросов.** Добавить: `Сколько стоит продвижение сайта во Франции?`
   (сейчас — «на французский рынок»). Это прямой ответ на `продвижение французского сайта цена`
   (позиция 12,1) и `продвижение сайта франция цена` (17,3).
6. **Первый абзац под H1** — по конвенции сайта он должен говорить, что ты выполняешь услугу.
   Название страны должно стоять в первом предложении.

Прилагательное «французский рынок» никуда не убирать — оно тоже работает. Задача не заменить, а добавить
вторую формулировку, которой сейчас почти нет.

## 3. Перелинковка

Сейчас на гео-страницы ведёт по сути только хаб `/ru/uslugi/lokacii` и редкие ссылки между соседними
странами. Что добавить:

1. **Анкоры на хабе** — сейчас все 16 ссылок звучат как «SEO-продвижение сайта на X рынок». Переписать
   на форму запроса: «Продвижение сайта во Франции», «Продвижение сайта в Швейцарии».
2. **Ссылки из блога.** Статьи про стоимость продвижения и мультиязычные сайты — естественные доноры.
   Ссылку ставить из тела текста, анкором с названием страны.
3. **Ссылка с главной или из услуги «SEO-оптимизация и стратегия»** на хаб стран — сейчас хаб получает
   вес только по навигации.

## 4. Как мерить

Не по кликам — их пока слишком мало, чтобы отличить сигнал от шума. Мерить по позициям конкретных
запросов из таблиц выше, снимок раз в две недели в GSC (фильтр по странице + вкладка «Запросы»).

Признак, что сработало: медиана кластера уходит ниже 10. Показов при этом станет меньше, а не больше —
уйдут мусорные показы с глубоких позиций, и это нормально.
